# Favoris TIDAL #7250 : le cache appartient au processus du témoin

Le cas visé est `favoris_tidal_plafonnes_route_et_cache_7250` dans le binaire
`services_remplacables_6336`. Le cache HTTP utilisateur est statique et indexé
par `(service, ressource)`, sans distinguer les états SQLite des tests.
Le test voisin de connexion TIDAL appelle les routes d’authentification qui
purgent ce cache. Entre les deux GET du témoin, cette purge peut provoquer
seize requêtes au faux fournisseur au lieu des huit attendues.

Le seul témoin #7250 s’exécute dans un processus neuf. Le parent exige un test
réellement réussi, sans cas ignoré. Les 357 identifiants, les huit requêtes puis
le cache, le miroir SQLite complet et la seconde synchronisation sans retrait
restent vérifiés par les assertions initiales. Le faux service conserve son
port alloué par le système ; aucun compte réel n’est sollicité.

Pour la contre-épreuve, désactiver seulement le retour du cache dans
`service_favorites` : le second GET doit faire échouer le compteur de requêtes.
Restaurer la production par copie, puis vingt passages sous charge.
