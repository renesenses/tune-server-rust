# Statut DR GET #8872 : vérifier les deux lectures coûteuses

Le témoin GET ne mesure plus le retard d’un métronome sous charge. Il observe
les vraies requêtes SQLite : inventaire des candidats et comptage des DR gravés
doivent tous deux quitter le fil unique de l’exécuteur. Leur compteur vaut deux,
et toutes les assertions de réponse restent conservées. Aucun délai mural ne
décide du verdict. Le témoin POST reste distinct dans cette PR.
La contre-épreuve appelle directement `statut_complet` depuis `statut`, sans
`spawn_blocking` ; elle doit nommer l’inventaire sur le fil async. Restaurer par
copie, puis vingt passages sous charge avec les mêmes assertions.
