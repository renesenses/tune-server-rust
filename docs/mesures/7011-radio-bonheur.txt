#7011 — Radio Bonheur : fiche du portail sans identifiant externe

Bertrand Clech / OpenAI Codex / bertrand-20261027-7011-c4d8
Base batch/bugs-rc9-20261025 : 4e982576bd8d9e358a24a61c60f9fa9b29d3361b.

Cause
Le cache réel annuaire-v2.json du .18 et la réponse réelle de l'annuaire
contiennent Radio Bonheur, id=1644, external_id=null, source=mozaiklabs,
status=active. Ce null est légitime : les fiches créées dans le portail ont
un id local ; external_id est réservé à l'identifiant radio-metadata importé.
RadioStation et RadioPresenter::v2 du portail confirment ce contrat.
Le parseur Tune perdait id ; le client emploie external_id pour jouer et
ajouter. Son clic construisait donc /directory/null/play/ZONE : 404 avant
l'orchestrateur, ce qui explique l'absence de tentative de lecture au journal.

Correctif
Conserver l'identifiant externe existant ; sinon utiliser mozaiklabs:ID
pour un id entier strictement positif. La clé reste stable après renommage
ou changement de flux. Aucun identifiant n'est inventé sans id valide.
La clé des titres en cours reste distincte et inchangée.
Le fixture vient de la fiche réelle du cache du .18 ; id, nom et URLs sont
anonymisés, structure et valeurs nulles conservées. Aucun accès à son URL.
